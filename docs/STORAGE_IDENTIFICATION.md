# Scoped identification, camera lookup and labels (S8 first increment)

The versioned identifier is `production-mf:v1:<organization UUID>:<container|location|batch>:<object UUID>`. It contains no credentials, actor/device proof, server action, mutable quantity or QA claim. Manufacturer lot is not a container identity. The manual form accepts either this complete typed code or an explicitly selected type plus UUID (case-insensitive manual UUIDs). Wrong organization, unknown type/version, actions, malformed IDs and arbitrary URLs fail before network lookup; arbitrary scanned text/URLs never enter durable storage.

`GET /inventory/identification?deviceId&organizationId&kind&id` uses fresh proof and current actor/grants under the organization inventory read lock. Container/location reads require current warehouse access. Batch lookup returns actual batch/order/product identifiers; production users without warehouse access may identify only batches in their current workshop route scope and receive no warehouse balance. Other-organization or wrong-kind identities do not resolve. A lookup never posts stock or grants permission.

The warehouse identification screen provides explicit server/manual/camera lookup, current identity/source/eligibility information, and navigation to package or exact location/subtree stock. Production-only issue screens provide own-batch identification. Storage's existing leased offline view also provides package/location lookup and up to 100 previously looked-up batches under the original local profile/server/organization/actor/device/epoch. Expired, revoked, switched or restored leases hide it. Offline results show the actual last-known timestamp and never promise current eligibility. Cache is not inventory truth, pending intent or audit; only its own bounded lookup-cache namespace can be evicted. Existing intents/ACKs/history remain preserved in v7 without reset/version change.

Camera use is explicit. The existing `html5-qrcode` decoder supports the warehouse code workflow, with manual fallback and no new product dependency. Android declares optional camera hardware and requests camera permission when the user opens scanning. The shared scanner now waits for pending startup during cleanup, preventing a camera from remaining active after the screen closes. Failed/denied camera access leaves manual lookup available. No decoded code can authorize a mutation.

Package, location and batch results provide QR/manual labels. The app can save an inert standalone HTML label and open browser or native Android printing. Labels include escaped human captions and exact typed IDs, never authentication data. SVG is restricted to static QR geometry; scripts, external resources and event attributes are rejected. The native print plugin uses an isolated local WebView with JavaScript, network and file/content access disabled, opening the actual platform print dialog. Opening a dialog is not a claim that paper was printed. Physical printer/label sizing/readability remains a pilot acceptance task.

Local verification includes real scoped PostgreSQL lookup tests; wrong scope/identity/epoch and sanitized-cache validation; offline lease/profile/expiry checks; escaped/inert label tests; and a red/green camera-startup cleanup regression. The actual two-profile browser creates real HTML/PDF labels and a deterministic video from the generated QR, feeds those frames to Chromium's camera, runs the real decoder, resolves the actual package through Fastify/PostgreSQL and confirms tracks stop afterward. It also checks all three offline identities, wrong-tenant/malformed credential-bearing input without network/persistence, and 390x844 / 412x915 readability. This virtual camera test does not certify a physical factory camera.

Route A is extended with actual native manual/server/offline lookup, wrong-tenant denial, an emulator camera stream that is stopped, and the real Android print-spooler dialog plus a screenshot. The harness grants camera permission only in the disposable instrumentation environment; normal application permission remains a user choice. **Hosted native verification of this S8 increment is pending.** No inventory schema migration is needed. S8 expiry/threshold alerts and ledger-matched reports/exports, plus S9–S10, remain unfinished.
