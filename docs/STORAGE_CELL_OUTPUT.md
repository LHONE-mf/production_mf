# Finished-cell output: authenticated submission API

This increment implements **submission and immutable serial-source ownership**, plus completed-step/catalog discovery and scoped history. It does not implement the production submission screen, durable server submission proposal/client ACK archive, physical cell warehouse acceptance, cell stock or Chief QA. Existing electrode acceptance is unchanged. No source, planned target, local observation or completed route automatically creates stock.

`POST /inventory/cell-outputs` requires a current Chief or Master, current actor/device proof, tenant, `x-inventory-epoch`, original operation/device identity and an allowed batch/order. Master needs current membership in the exact immutable route workshop; warehouse grants alone confer no production submission rights. Authority is checked inside the inventory transaction and proof/session validity again after database lock waits before commit. Suspended posting and old history fail closed, including retries.

The strict request contains `operationId`, `deviceId`, `productionBatchId`, `stepNumber`, `completionId`, explicitly selected `materialId`, `source`, `reason`, `evidence`. Source is a versioned, allowlisted projection of an existing immutable `FormationSerialIdentity`; full originals remain on the device. It preserves identity/Formation/Assembly-output/operation/filling/receipt/optional-walzing/input IDs, actual cell format, full original input serial prefix/range, explicitly declared processed ranges, original Formation author/role/time/calendar dates/counts/units/entered observations, and original declaration author/role/time/evidence. The projection drops unknown local metadata without rewriting the original.

The source must have a declared end date and conserve **input = processed + scrap + unknown**. Every processed serial is explicit, within the full input, sorted and nonoverlapping; up to 1000 ranges, totaling exactly the positive processed count. Safe integers only, no serial expansion or inferred subset. Full input 10–13 with processed serials 10 and 12 still has four inputs; the app does not identify the other serials as scrap/unknown. Local author/role is attribution, not server authentication, equipment verification, final QC or physical cathode/anode pairing.

The server completion must be an actual `completed` event in `pieces` with exactly that processed count, on the final applicable **Formation/common** step of a **cell** batch. Any later common route step blocks submission from the earlier step. No new aging route or final-QC rule is invented. Planned quantities and journal text are ignored. Material must be an active cell catalog item in pieces; free-form names do not infer chemistry, cell format or pairing. Selection is explicit.

Migration **032** adds immutable `inventory_cell_submissions` and `inventory_cell_serial_ranges`, preserving populated 001–031 rows, stock, electrode sources/receipts and all old queues. Main Dexie **23** and inventory outbox **v7** are unchanged. One completion, explicit identity, Formation result, Assembly output and Assembly run can be offered once per tenant. The full original input serial domain is held atomically across devices; different prefixes are distinct only when both are nonempty. An absent/empty prefix conservatively conflicts with overlapping numbers under any prefix. Disjoint processed subsets cannot bypass whole-source ownership through aliases. Unknown/scrap serials are not silently freed or reassigned. Cancellation/correction needs a future explicit immutable resolution.

Stored serial rows must exactly pair with the source's original ordered ranges; deferred checks reject incomplete/orphan submissions. Result ACK, request, count, actor/device and revision pair with the same original source. Both tables are immutable. The shared operation-ID guard forbids adopting stock/issue/outcome/count/electrode operation IDs, including generated-column BEFORE-trigger NULL cases. Submission has `stock_effect=false`, no stock package, no warehouse ledger movement and no QA event.

The response has `status: confirmed|duplicate`, `operationId`, `submission`; submission retains original request fields plus actual `quantity`, `unit: pieces`, `revision: 1`, authenticated server actor and server time. Exact original actor/device/body retries return the original accepted snapshot even after a later batch hold; current authority/proof/history/posting fence still apply. Different IDs cannot submit the same source or overlapping serial domain again. Original client intent must never be rebased to a new epoch automatically.

`GET /inventory/cell-outputs` returns tenant-scoped UUID-cursor history, at most 100 records, optional batch filter, exact epoch/posting context and original source/ACK. Chief/warehouse readers see their tenant; Master without warehouse rights sees only current-workshop sources. Read history is submission evidence, not confirmed cell stock or a frozen export snapshot.

`GET /inventory/cell-outputs/steps` offers actual eligible final completions, excluding already offered completions. `/inventory/cell-outputs/materials` requires the exact eligible batch/step/completion and offers active cell-piece materials. Both are Chief/current-workshop Master only, explicitly paginated to 100, and preserve current proof/history context. They never generate stock or output from planned targets.

Verification includes real proofed Fastify/PostgreSQL role/tenant/quantity/range/duplicate/race/revocation/expiry/restore tests, direct database namespace/orphan/ACK/immutability checks, original local identity projection, actual additive populated upgrade and 49-table/two-restore drill. The expanded native harness exercises this API with a real saved explicit identity and lost-reply exact retry; that is API coverage, not a new product submission/physical acceptance screen. Exact hosted/source evidence is recorded in the checkpoint.
