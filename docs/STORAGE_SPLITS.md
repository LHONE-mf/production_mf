# Authorized split, repack and partial movement (S6)

Chief or an explicitly granted Warehouse Manager authorizes one new child per operation. Repeat with new intent for more children. The remaining parent keeps its identity, location and **all owned reservations**. Exact positive base-unit quantity cannot exceed the parent's unreserved amount. Full repack is allowed when no reservations prevent it, retaining an empty historical parent rather than deleting it. Arbitrary pooling/merge is absent.

`POST /inventory/stocks/:stockId/splits` takes `operationId,childOperationId,deviceId,parentStockId,childStockId,locationId,expectedRevision,quantity,reason,evidence`, fresh proof and original `x-inventory-epoch`. It rechecks current manager authority after the organization inventory lock. One transaction debits the parent, creates a fresh child at the explicit active destination, appends `split_out` and `split_in` to the existing immutable stock ledger, and records immutable `inventory_splits` genealogy/authorization. All three records pair through DB constraints. Parent before/after plus child quantity conserve exactly; material/lot/unit/QA/disposition/manufacture/expiry are inherited. The child receives no reservation. Exact retry replays the original two snapshots; changed IDs, collisions, stale revisions, other organizations and revoked/history-held requests fail without partial stock.

Split is packaging, never QA release. Quarantined/held material retains its state. Ancestor holds and expiry restrict descendant use, including mixed return/split ancestry; a child QA release cannot override an ancestor hold. Existing issue approval becomes stale if splitting changes its parent stock revision, requiring explicit reapproval.

Migration **028** is additive and does not invent genealogy for old packages. Existing balances/reservations/events and populated prior-schema upgrade survive. Application rollback must retain new stock kinds and genealogy evidence; never delete child history or fabricate a reverse movement.

`InventorySplitPanel` provides exact quantity, active destination, reason/witness, online privilege review, separate explicit physical confirmation/send, retained original requests/ACKs/conflicts, and paginated genealogy for both parent and child. Typed raw fields persist locally. Stale drafts require explicit new-draft confirmation and do not silently follow refresh. A frozen split survives reopen/lost ACK. Both stock snapshots, both retained ACKs and accepted proposal commit in one local transaction. Arbitrary response fields do not enter storage. InventoryOutbox stays **v7**, with original-profile `split` and `split-form` namespaces; recovery includes them without automatic replay or reset.

Every package now has a QR/manual label containing only the versioned organization/type/container identity. It is not authorization and contains no credentials or mutable quantity/QA claims. Strict parsing rejects malformed, wrong-organization and action-bearing labels. S6 verifies child lookup against the authorized cache and original-parent genealogy. Full camera/manual navigation, location/batch labeling, printing and reporting remain S8 work.

Real PostgreSQL tests cover current privileges, reservation preservation, full repack, paired DB guards/immutability, competing requests, ID/package collisions, tenant/history fencing, inherited holds and populated upgrade. Client tests cover reopen/lost ACK, two-stock/two-ACK atomicity, forged quantities/dates and retained conflicts. Actual two-profile Chromium uses the physical-confirmation screen, loses the committed ACK, retries once and resolves the child label/genealogy. Actual dump/two restores compare **41 tables**, reconstruct **13 stock events / four stocks / one reservation / one issue / five handoff events / two outcomes / one split**, and retry the split unchanged after restore. The extended Route A native assertions must still pass at the S6 commit's exact SHA; consult PR #5. Physical/device/deployment acceptance remains separate.
