## Bounded offline recovery milestone — 2026-11-14

This supersedes the earlier cold-start catalogue/access limitation. InventoryOutbox v5 adds `offlineViews` without resetting existing forms, queues, stock, history or cursor. A complete authenticated refresh may cache catalogue data and access flags under a grant returned by `/inventory/access/me`. The server rechecks current actor/device/session/warehouse access in one authorization snapshot. Grant expiry is the minimum of the original server session expiry and original device-proof creation plus eight hours; the client also caps it by the current local-login expiry. No bearer/proof token, password or signing key is persisted.

The cached view binds server origin, organization, actor, enrolled device, local user and local-login issuance. A local generation marker provides immediate durable revocation even if clearing IndexedDB fails. Explicit server/local logout, account/device/server changes and authenticated HTTP 401/403 remove cached-view access without deleting pending work. Expiry or a detected clock rollback fails closed; observing expiry cannot renew access by moving the clock back. Cache shape, units, identities, permissions and physical hierarchy are validated before use. An old server without the optional grant still supports online operation but cannot provision this offline capability.

After a restart, a verified original local login can explicitly open the last-known inventory while the grant remains valid. The screen identifies the original server/org/device, last successful sync and expiry; it labels quantities as stale last-known data. Receiving, whole-container movement and eligible correction forms can freeze provisional work against the original revision. The offline screen has no send action or server credentials. Fresh server login/device proof and explicit send confirmation remain required; all posting permissions are rechecked by the server. Users may close saved access without clearing drafts/queues.

Revocation while genuinely disconnected cannot be immediate: the remaining server-issued window is the explicit upper bound. Native encrypted-storage/key/OS acceptance and physical policy remain pilot gates; this capability is neither a server authorization token nor a cross-device backup/restore mechanism. New local login issuance cannot adopt an old cached grant.
